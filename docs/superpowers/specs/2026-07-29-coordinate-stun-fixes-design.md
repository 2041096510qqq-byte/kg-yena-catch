# 元素生成位置与眩晕定位修复设计

## 目标

修复两个初版问题：

1. 下落元素在屏幕中部出现，而不是从 Yena 手部附近出现。
2. 玩家进入眩晕状态时移动到画面最左侧，而不是留在原地。

眩晕持续时间保留当前产品决定的 2 秒。除明确相关的生成位置和横向范围外，不调整其他玩法数值。

## 根因

### 元素生成位置

游戏逻辑中的元素 `x/y` 是相对 750×1334 整个设计画布的归一化坐标。`CoreStage` 渲染时也按整屏尺寸把坐标转换为像素，但容器自身又设置了 `top: 25%`，导致纵向位置被重复加上约四分之一屏。当前 `ELEMENT_SPAWN_Y = 0.30` 因而实际显示在约 55% 屏高处。

### 眩晕位置

玩家外层节点的内联 `transform` 用于横向定位。`.player-sprite.stunned` 的 `shake` 动画也在同一个节点上修改 `transform`，动画运行时覆盖内联定位，令横向位移回到 `0 ± 10px`，表现为玩家跳到最左侧。

## 设计

### 统一舞台坐标

- `CoreStage` 覆盖完整 750×1334 游戏画布，不再通过 `top` 和 `bottom` 建立第二套局部坐标。
- 元素、粒子、碰撞反馈继续使用现有的整屏归一化坐标，不增加坐标换算层。
- `ELEMENT_SPAWN_Y` 设为 `0.25`，使元素中心从约 25% 屏高、即 Yena 手部区域附近出现。
- `YENA_HAND_X_VARIANCE` 恢复为 PRD 定义的 `0.15`，生成范围保持在画面中心左右各 15%，与“从手部丢出”的语义一致。
- 保持 `CoreStage` 的层级低于 Yena 和玩家，使元素从角色立绘附近出现时仍有自然的前后遮挡关系。

### 分离定位与眩晕动画

- 玩家外层 `.player-sprite` 只负责绝对定位和每帧横向 `transform`。
- 眩晕 `shake` 动画应用于内部 `.player-img`，动画只产生局部 `±10px` 抖动。
- 星星特效继续相对玩家外层定位，因此玩家眩晕期间角色和特效都保持在碰撞发生时的横向位置。
- 游戏循环进入眩晕时继续把目标位置锁定到当前 `playerX`；眩晕期间忽略输入，结束后恢复移动。
- `STUN_DURATION` 保持 `2000ms`，无敌时间保持 `1500ms`。

## 测试策略

新增可独立测试的纯坐标/样式约束，先写失败测试再修改实现：

1. 元素生成纵坐标应为整屏 `0.25`，渲染容器不得再叠加顶部偏移。
2. 横向生成偏移应为 `±0.15`。
3. 眩晕动画不得作用于 `.player-sprite` 的 `transform`，应作用于 `.player-img`。
4. 生产构建必须通过，确保 TypeScript 和 Less 均可编译。

完成后启动本地页面进行视觉验证：元素从 Yena 手部附近出现；将玩家移到非中心位置后触发眩晕，玩家应在原位置附近抖动且不跳到左侧。

## 非目标

- 不把眩晕恢复为 PRD 初稿中的 5 秒。
- 不调整掉落速度、碰撞区域、得分、Combo 或 Fever 逻辑。
- 不重构与这两个问题无关的页面和素材代码。
