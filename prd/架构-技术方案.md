## 玩法运行时模型（TSCRV）— 动力学 SSOT

> 分流闸判定：`T ≠ event`（玩家不操作，元素仍会下落——画面会自己变）+ `S ≠ none`（元素有空间位置和碰撞判定）
> → **simulation-type**，填全五轴表。

| 轴 | 取值 | 本作具体化 |
|---|------|-----------|
| **T 时间** | `realtime` | **tick 源**: rAF（requestAnimationFrame），变步长（Δt）。**阶段序**: 输入处理 → 生成判断 → 移动更新 → 碰撞检测 → 结算处理 → 计时更新 → 渲染。玩家不操作时元素继续下落、计时继续推进。 |
| **S 空间** | `continuous-2d` | **坐标系**: 屏幕坐标，原点左上角，设计稿 750×1334。**碰撞判定**: 元素碰撞框（50-72px 方形）与小人碰撞框（60×60px）矩形重叠面积 ≥ 50%。**边界**: 小人 x ∈ [10%, 90%] 画面宽，下落元素 x ∈ [5%, 95%]，y 从 Yena 手部位置 → 底部外销毁。y 轴方向：上方生成 → 下方下落。 |
| **C 操作** | `drag` + `tap` | **触摸拖动**: 手指在底部操作区（画面 y 下 40%）滑动 → 小人 x 坐标跟随手指，受边界约束 `clamp(x, minX, maxX)`。**点击移动**: 点击画面左半区 → 小人向左移动，右半区 → 向右移动（辅助方案）。**眩晕期间**: 所有操作全部失效。 |
| **R 规则** | 生成 + 运动 + 碰撞 + 计分 + Fever | **一个 tick 的阶段序**: ① 读取当前��摸位置，更新小人目标 x。② 按当前时间段查掉落参数表（间隔、概率），判断是否生成新元素；若是，按概率随机类型，在 Yena 手部 x 位置（含 ±15% 随机偏移）生成。③ 推进所有元素 y += speed×Δt，爱心附加 x += sin(phase)×振幅。④ 遍历元素，检测与小人碰撞框重叠 ≥50%；命中 → 触发得分/惩罚/Combo/Fever 逻辑。⑤ 更新 Combo 阈值判定、Fever 槽增减、眩晕计时。⑥ 更新倒计时、Fever 计时、眩晕计时。**规则细节**见 PRD §3-4。 |
| **V 视图** | `fixed-single` × DOM+CSS | **投影**: fixed-single（单屏，无滚动无相机）。**量化事实**: `maxConcurrentEntities` = 8 元素 + 1 小人 + ~30 粒子 = ~39；`needsPhysicsSolver` = false（脚本轨迹，非真实物理）；`worldLargerThanViewport` = false；`needsPerPixel` / `needs3D` / `skeletal` 均 false。→ **衬底判定**: 所有硬门槛均不触发 → **DOM + CSS**（无渲染引擎）。详情见下「渲染框架决策」。 |

### 反例自检

与本作数据模型最接近的同构品类 = **「接落物」类游戏**（如接水果、接金币）。

本作与通用接落物的具体差别：
1. **眩晕惩罚**（不是扣血，是剥夺移动权 5 秒）→ 需要独立 STUNNED 子状态 + 无敌窗口
2. **Fever Time**（接道具充能→10 秒双倍+无炸弹）→ 需要 Fever 槽累加器 + 双倍计分 + 概率表动态切换
3. **Combo 称号系统**（5 级阈值 + 额外加分）→ 接落物通常没有 Combo 加成
4. **局内 4 段难度递进**（不同时间段不同掉落参数）→ 需要时间驱动的概率表切换
5. **三分法掉落决策**（爱心稳分/道具冲分/炸弹风险）→ 掉落不是随机，而是有意设计的接/躲决策张力

## 渲染框架决策

### 输入事实（从 TSCRV V 轴）

| 事实 | 值 | 说明 |
|------|-----|------|
| `maxConcurrentEntities` | ~39 | 8 元素 + 1 小人 + ~30 Fever 粒子 |
| `perFrameMutatedNodes` | ~40 | 每帧需更新 transform 的 DOM 节点 |
| `needsPhysicsSolver` | false | 脚本轨迹，非真实物理 |
| `worldLargerThanViewport` | false | 单屏 |
| `needsPerPixel` | false | — |
| `needs3D` | false | — |
| `skeletal` | false | — |

### 决策 A：模拟运行时
- `hasLoop` = true → rAF 循环落 Hook（`useGameLoop`），变步长
- `needsPhysicsSolver` = false → 无物理库

### 决策 B：渲染衬底
- **起点 DOM + CSS**
- 逐条过硬门槛：
  - 大规模同屏运动（≥100）→ ❌ 不触发（~39）
  - 真实粒子系统（成百上千）→ ❌ 不触发（~30 个 CSS 粒子）
  - 2D 物理渲染负载 → ❌ 不触发
  - 像素级 Canvas 操作 → ❌ 不触发
  - 骨骼动画 → ❌ 不触发
  - 大世界相机 → ❌ 不触发
- **结论：DOM + CSS（无渲染引擎）**

> 选型说明：39 个 DOM 节点的 transform 更新在 60fps 下完全可承受，CSS `transform` 走 GPU 合成层不触发 reflow。Fever Time 粒子用 `@keyframes` + 绝对定位的 `<div>` 实现，生命周期由 JS 管理。

## 关键类型定义

```typescript
// ===== 枚举 =====

enum GameState {
  IDLE = 'IDLE',           // 主界面
  COUNTDOWN = 'COUNTDOWN', // 3-2-1 倒计时
  PLAYING = 'PLAYING',     // 游戏中
  PAUSED = 'PAUSED',       // 暂停
  RESULT = 'RESULT',       // 结算
}

enum SubState {
  NONE = 'NONE',           // 正常
  STUNNED = 'STUNNED',     // 眩晕
  FEVER = 'FEVER',         // Fever Time
}

enum Difficulty {
  EASY = 'easy',
  NORMAL = 'normal',
  HARD = 'hard',
}

enum ElementType {
  HEART = 'heart',         // 爱心 +1
  ITEM = 'item',           // YENA 道具 +5
  BOMB = 'bomb',           // 炸弹 -2+眩晕
}

// ===== 实体 =====

interface GameElement {
  id: string;
  type: ElementType;
  x: number;               // 归一化 0-1（实际渲染时 ×750）
  y: number;               // 归一化 0-1（实际渲染时 ×1334）
  speed: number;           // 归一化速度（/s）
  swingPhase: number;      // 爱心摇摆相位（0-2π），非爱心为0
  swingAmplitude: number;  // 爱心摇摆振幅，非爱心为0
  spawnTime: number;       // 生成时间戳（ms），用于生命周期判定
}

interface Particle {
  id: string;
  x: number;               // 归一化
  y: number;
  vx: number;              // 水平速度（归一化/s）
  vy: number;              // 垂直速度
  life: number;            // 剩余生命 ms
  maxLife: number;
  color: string;           // CSS 颜色
  size: number;            // px
  shape: 'circle' | 'star' | 'smoke';
}

// ===== 游戏配置 =====

interface PhaseConfig {
  startTime: number;       // 秒
  endTime: number;         // 秒
  spawnInterval: number;   // 生成间隔 秒
  heartProb: number;       // 0-1
  itemProb: number;        // 0-1
  bombProb: number;        // 0-1（heartProb+itemProb+bombProb=1）
}

interface DifficultyModifier {
  speedMultiplier: number; // 速度倍率
  bombProbOffset: number;  // 炸弹概率偏移
  stunDuration: number;    // 眩晕时长 秒
  targetScore: number;     // 4星目标分
}

// ===== 帧输入 =====

interface FrameInput {
  pointerX: number | null; // 归一化触摸 x，null=无触摸
  pointerActive: boolean;
}
```

## Hook 设计

### useGameLoop(gamePageRef, elementsRef, particlesRef)

> 核心游戏循环。在 `GamePage` 挂载时启动 rAF，卸载时取消。

- **输出**: `{ startLoop, stopLoop, isRunning }`
- **内部状态**: `rafIdRef`, `lastTimeRef`, `frameInputRef`（当前帧的触摸输入）
- **核心逻辑**:
  1. rAF 回调：计算 Δt = 当前时间 - lastTime
  2. **输入处理**: 读取 `frameInputRef` 中的触摸位置，更新 `targetPlayerXRef`
  3. **生成判断**: 查当前时间段参数表，若距上次生成 ≥ spawnInterval → 按概率随机类型 → 创建 GameElement push 到 `elementsRef`
  4. **移动更新**: 遍历 elementsRef → y += speed×Δt，爱心附加 x += sin(swingPhase+speed×Δt)×振幅。遍历 particlesRef → x += vx×Δt, y += vy×Δt, life -= Δt → life≤0 的标记移除
  5. **碰撞检测**: 遍历 elementsRef，检测与小人碰撞框是否重叠 ≥50% → 命中则触发结算
  6. **结算处理**: 调用 Redux dispatch（addScore/setCombo/incrementFeverGauge/triggerStun 等）
  7. **计时更新**: 每秒 dispatch tick 更新倒计时/眩晕/Fever/无敌。倒计时归零 → dispatch endGame
  8. **DOM 渲染**: 遍历 elementsRef → 更新对应 DOM 元素 ref 的 `style.transform`。遍历 particlesRef → 同上。更新小人 ref 的 `style.transform`
  9. 请求下一帧 rAF

> ⚠️ 游戏循环体**不 dispatch Redux 每帧**。只有碰撞事件、每秒计时、状态变化时才 dispatch。实体位置更新直接操作 DOM ref。

### useGameInput(playerAreaRef)

- **输出**: `{ frameInputRef }`（被 useGameLoop 每帧读取）
- **内部状态**: `touchActiveRef`, `currentXRef`
- **核心逻辑**: 监听 `touchstart/touchmove/touchend`（移动端）+ `mousedown/mousemove/mouseup`（PC）。仅在 PlayerArea 内生效。计算归一化 x，写入 `frameInputRef.current.pointerX`。眩晕期间忽略所有输入。

### useCollision()

- **输出**: `{ checkCollision(element, playerX): boolean }`
- **核心逻辑**: 矩形重叠面积计算。`overlapArea / min(elementArea, playerArea) ≥ 0.5`

### useGameAudio()

- **输出**: `{ playBGM(), stopBGM(), playSFX(type), setMuted() }`
- **内部状态**: `bgmRef`（HTMLAudioElement 或 Web Audio 节点）
- **核心逻辑**: 短音效用 `AudioContext` + `OscillatorNode` 合成（无外部音频文件依赖）。BGM 用 `<audio>` 元素加载。加载失败静默降级。

### useParticles(elementsRef, particlesRef)

- **输出**: `{ spawnParticles(type, x, y, count) }`
- **核心逻辑**: 根据事件类型（接住爱心/道具/炸弹/Fever）生成对应粒子配置 → push 到 particlesRef

### useCountdown(seconds, onEnd)

- **输出**: `{ count, isCounting, start() }`
- **核心逻辑**: 从 seconds 倒数到 0，每秒回调，0 时调用 onEnd。用于 3-2-1 游戏开始倒计时。

## 性能约束

> 固定红线（首屏 <3s / JS <200KB gzip / 图片 <1MB / 动画 ≥30fps / 0 泄漏 / Canvas ≤屏高 50-60%）见 SKILL.md「性能红线」。本项目额外约束：

| 额外指标 | 目标 | 实现手段 |
